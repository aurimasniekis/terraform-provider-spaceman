# spaceman_harness_profile (Resource)

A harness profile (`GET /harness-profiles`, `PUT /harness-profiles/{id}`): harness, model and settings a role template starts from. An update bumps the revision and applies to later launches. SpaceMan has no API to delete a profile: destroying the resource only removes it from Terraform's state.

## Example Usage

```terraform
resource "spaceman_harness_profile" "careful" {
  slug     = "careful"
  name     = "Careful Claude Code"
  harness  = "claude-code"
  model    = "claude-sonnet-4-5"
  settings = { permission_mode = "default" }
}

# Claude Code settings.json keys for the profile's runs: any keys. "$defaults" keeps
# Claude Code's built-in rules in an auto mode list.
resource "spaceman_harness_profile" "auto" {
  slug     = "auto"
  name     = "Claude Code in auto mode"
  harness  = "claude-code"
  settings = { permission_mode = "auto" }

  claude_settings = jsonencode({
    autoMode = {
      environment = ["$defaults", "Source control: GitHub repositories of example-org, reached through the gateway host."]
      allow       = ["$defaults", "Pushing feature branches to the space's repositories is allowed; main only through pull requests."]
    }
    permissions = {
      ask  = ["Bash(git push --force:*)"]
      deny = ["Read(./secrets/**)"]
    }
    env = { GIT_TERMINAL_PROMPT = "0" }
  })
}
```

## Schema

### Required

- `harness` (String) `claude-code` or `codex`. Fixed after creation.
- `name` (String) Display name.
- `slug` (String) Unique identifier. Fixed after creation.

### Optional

- `claude_settings` (String) Claude Code `settings.json` keys for the profile's runs, as a JSON object (`jsonencode({...})`): any keys, such as `permissions`, `autoMode`, `env` or `hooks` (`claude-code` profiles only; ADR-0059). SpaceMan sets them in each run's own `settings.json` at launch. `permissions.defaultMode` is held to central's permission mode ceiling. Hooks run commands on the node, and the settings are stored in clear, so keep secrets out. The server's key order never causes a diff. Removing the attribute or setting `jsonencode({})` clears the settings; SpaceMan stores both as no settings, so an import reads either as unset. A warning flags `env` keys that look like credential or endpoint overrides (`ANTHROPIC_*`, `CLAUDE_CODE_*`, `*_PROXY`).
- `description` (String) Description.
- `model` (String) Model.
- `settings` (Map of String) Harness settings (string values).

### Read-Only

- `id` (String) The profile ID.
- `revision` (Number) Increments on every change.
