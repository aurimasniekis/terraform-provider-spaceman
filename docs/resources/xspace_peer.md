# spaceman_xspace_peer (Resource)

One space's side of a cross-space grant with a peer space (`PUT/DELETE /spaces/{id}/xspace/peers/{peer_id}`, ADR-0038): what the space accepts from the peer (`inbound`) and what its control may send to it (`outbound`). A request from S to D needs D's inbound flag **and** S's outbound flag, so a working pair needs two resources, one per side. Every flag is off unless set. Because this is an authorization grant, Terraform owns the whole configuration: a flag turned on in the UI shows as drift. Destroying the resource removes the configuration (nothing is allowed with that peer from this side); requests already open stay open.

## Example Usage

```terraform
# Payments accepts questions and knowledge requests from Platform ...
resource "spaceman_xspace_peer" "payments_from_platform" {
  space_id = spaceman_space.payments.id
  peer_id  = spaceman_space.platform.id
  inbound = {
    discover        = true
    questions       = true
    knowledge       = true
    knowledge_bases = ["docs"]
    disclosure      = "summary"
    max_per_hour    = 10
  }
}

# ... and Platform's control may send them (both sides must agree).
resource "spaceman_xspace_peer" "platform_to_payments" {
  space_id = spaceman_space.platform.id
  peer_id  = spaceman_space.payments.id
  outbound = {
    questions = true
    knowledge = true
  }
}
```

## Schema

### Required

- `peer_id` (String) The peer space (not the same space).
- `space_id` (String) The space whose side this is.

### Optional

- `inbound` (Attributes) What this space accepts from the peer. (see [below for nested schema](#nestedatt--inbound))
- `outbound` (Attributes) What this space's control may send to the peer. (see [below for nested schema](#nestedatt--outbound))

### Read-Only

- `id` (String) `<space_id>/<peer_id>`.

<a id="nestedatt--inbound"></a>
### Nested Schema for `inbound`

### Optional

- `delegation` (Boolean) The peer may ask this space's control to do work; this space decides and runs it. Default `false`.
- `disclosure` (String) What replies to the peer may contain: `none` (default, the outcome only), `summary` (text up to 2,000 characters), `detailed` (text up to 20,000 characters and KB evidence).
- `discover` (Boolean) The peer's control may see this space and its profile (not needed to ask). Default `false`.
- `knowledge` (Boolean) The peer may ask this space's knowledge bases (through support sessions, never the repository). Default `false`.
- `knowledge_bases` (Set of String) KB slugs the peer may ask; empty (default) means every enabled knowledge base.
- `max_pending` (Number) Requests from the peer open here at once (1-100, default 5).
- `max_per_hour` (Number) Requests the peer may send here per hour (1-1000, default 20).
- `questions` (Boolean) The peer may ask this space's control questions. Default `false`.

<a id="nestedatt--outbound"></a>
### Nested Schema for `outbound`

### Optional

- `delegation` (Boolean) Control may ask the peer's control to do work. Default `false`.
- `knowledge` (Boolean) Control may ask the peer's knowledge bases. Default `false`.
- `questions` (Boolean) Control may ask the peer's control questions. Default `false`.
