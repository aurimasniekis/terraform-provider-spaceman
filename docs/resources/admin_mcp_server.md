# spaceman_admin_mcp_server (Resource)

A SpaceMan MCP server (`POST /mcp-servers/spaceman`): SpaceMan's own API offered as MCP tools to a space's control and worker runs. It acts through an internal API token that SpaceMan mints for it, owned by the user whose API token the provider uses, with `grants` covered by that user's own. The token has no secret, so nothing here is sensitive and nothing secret is stored in the state. Runs see the tools only through a `spaceman_mcp_grant` (space and role).

The provider must use an API token issued by a user (not the root token, and not a token issued by another token): SpaceMan refuses otherwise. Changing `grants` or the expiry re-issues the internal token in place (SpaceMan revokes the old one and mints a new `token_id` in one step); every other change is an in-place edit. Deleting the server revokes its token and removes its grants. Dangerous tools (deletes, secrets, profile hooks and the like) always need a person's approval in SpaceMan, whatever `approval` says. Use `spaceman_mcp_server` for external (http) MCP servers; each resource refuses the other kind.

Reading the server (every refresh and plan) lists its effective tools through SpaceMan's `check-mcp-server`, which needs `mcp:write`: the provider's token needs that permission (for example `admin` on `*`) even to plan.

## Example Usage

```terraform
# SpaceMan's own API as MCP tools for an infra space's control runs. The provider must use an API token issued by a
# user (not the root token): the server's internal token is owned by that user, with grants covered by theirs.
resource "spaceman_admin_mcp_server" "admin" {
  slug   = "sm-admin"
  name   = "SpaceMan admin"
  preset = "operate" # read and write tools; dangerous ones only by name (and always approved by a person)
  tools  = ["delete_schedule"]

  # The internal token's grants. Changing them (or expires_in_days) re-issues the token: a new token_id.
  grants = [
    { role = "operator", domain = spaceman_space.payments.id },
  ]
  approval        = "writes" # every write tool needs a person's approval too
  expires_in_days = 90
}

# Only granted roles' runs see the tools.
resource "spaceman_mcp_grant" "admin_control" {
  server_id = spaceman_admin_mcp_server.admin.id
  space_id  = spaceman_space.payments.id
  role      = "control"
}

output "admin_mcp_tools" {
  value = spaceman_admin_mcp_server.admin.effective_tools
}
```

## Schema

### Required

- `name` (String) Display name (also the internal token's name).
- `slug` (String) Namespace of the server's tools (`<slug>__<tool>`): 1-31 lowercase letters, digits or dashes, starting with a letter. `spaceman` is reserved (it is the built-in agent server). Changing it replaces the server (and drops its grants).

### Optional

- `approval` (String) `none` (the default): only dangerous tools need a person's approval; `writes`: every write tool does too. Dangerous tools are always gated by SpaceMan.
- `call_timeout_ms` (Number) Timeout of one tool call, 1000-20000 (server default when left out).
- `description` (String) Description.
- `enabled` (Boolean) Whether the gateway offers the server's tools (default `true`).
- `expires_in_days` (Number) Lifetime of the internal token in days (1-366), counted from when it is minted. Left out, the token never expires (the default). Changing it re-issues the token; change it again (or re-apply with a new value) to renew an expired one.
- `grants` (Attributes Set) The internal token's role grants, each covered by the provider user's own. Left out at create, SpaceMan grants `admin` on `*` (only with the `admin` preset; other presets need grants). Changing them re-issues the token (new `token_id`). Removing them from an existing server is refused at plan time (it would neither widen the token to `admin` on `*` nor silently keep the old grants): set them explicitly. A server whose grants are already exactly `admin` on `*` may leave them out. (see [below for nested schema](#nestedatt--grants))
- `max_concurrency` (Number) Calls in flight to this server across all runs, 1-32 (server default when left out).
- `max_result_bytes` (Number) Largest tool result passed to an agent, 1 KiB-4 MiB (server default when left out).
- `never_expires` (Boolean) Whether the internal token never expires: `true` exactly when `expires_in_days` is left out (setting it is optional and only documents the choice).
- `preset` (String) Tool set: `read`, `operate` (read and write), `admin` (read, write and dangerous; the default) or `custom` (only the tools named in `tools`).
- `tools` (Set of String) Tools added to the preset by name, without the slug (for example `delete_task`). Dangerous and sensitive-read tools are offered only by name or by the `admin` preset.

### Read-Only

- `effective_tools` (Set of String) The tools the server offers runs (without the slug), as SpaceMan resolves the preset, `tools` and the token's grants. Empty when the token can no longer be used.
- `expires_at` (String) When the token expires (RFC 3339); empty when it never does.
- `id` (String) The server ID.
- `owner_user_id` (String) The user whose authority the token carries: the provider's user at the last (re-)issue.
- `token_id` (String) The internal API token the server acts through (no secret exists for it).
- `token_state` (String) `active`, or why the server's tools are refused (`revoked`, `expired`, `owner_disabled`): re-issue it by changing `grants` or `expires_in_days`.
- `version` (Number) The server's version (increments with every change).
