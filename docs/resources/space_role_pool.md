# spaceman_space_role_pool (Resource)

The accounts one role of a space may use when a run reaches a usage limit (`PUT /spaces/{id}/account-pools/{role}`, SpaceMan ADR-0090). A role with a pool uses only these accounts instead of the space's pool; each must also be bound to the space first (`spaceman_space_accounts`): add `depends_on` for the binding resource. The resource owns the role's whole pool, so entries added in the UI show as drift. Destroying it removes the role's pool, and the role uses the space's pool again. Needs a SpaceMan release with account pools (0.1.8 or later).

## Example Usage

```terraform
resource "spaceman_space_role_pool" "worker" {
  space_id = spaceman_space.payments.id
  role     = "worker"
  # The accounts must be bound to the space first.
  depends_on = [spaceman_space_accounts.payments]
  account = [
    { account_id = spaceman_account.claude_a.id, priority = 10 },
    { account_id = spaceman_account.claude_b.id, priority = 20 },
  ]
}
```

## Schema

### Required

- `account` (Attributes Set) The pool's accounts. (see [below for nested schema](#nestedatt--account))
- `role` (String) The role name (the space role's `name`): lower-case letters, digits and `-`, starting with a letter, at most 48 characters. Changing it updates the pool in place: the pool is written under the new name and the old name's pool is removed if it is still there. Renaming the `spaceman_space_role` this references moves the pool with it. Do not swap the roles of two pool resources in one apply: removing the old name's pool can remove the pool the other resource just wrote, so swap them in two applies.
- `space_id` (String) The space.

### Read-Only

- `id` (String) `<space_id>/<role>`; changes when `role` changes.
